## 1. 需求说明

### 1.1 需求名称

内容基本信息创建与编辑

### 1.2 需求类型

NEW

### 1.3 版本信息

NEW 需求，本节写「无」。

### 1.4 背景

运营需要以主数据形式先建立内容记录（标题、类型、时间），再逐步补齐展示配置与模块；内容记录是后续模块编排与发布动作的载体。回链 Epic 背景见 `EPIC.md` §1。

### 1.5 目标

- 运营可创建内容并保存基本信息，内容进入「待发布」。
- 内容类型决定默认模板；内容类型创建后不可修改。
- 基本信息可编辑（受状态约束的部分除外）。

### 1.6 范围

本次需求包含：

- 创建内容（基本信息表单）
- 编辑基本信息（标题、时间、摘要、说明等）
- 查看内容详情（基本信息区）

---

## 2. 功能说明

### 2.1 功能概述

提供内容主数据的创建、编辑、查看能力；创建成功后内容状态为 DRAFT（待发布）。

### 2.2 适用场景（业务视角）

> 本节仅说明谁会使用本功能，**不是权限主体**。权限以权限码控制，见 §3 与 `shared-context.md` §2。

| 使用方 | 说明 | 典型场景 |
|---|---|---|
| 内容运营 | 内容的配置负责人 | 公告 / 帮助文档立项建卡 |
| 客服运营 | 帮助内容维护者 | 查看内容时间与状态，协调更新节奏 |

### 2.3 主要业务对象

> 跨场景对象只列对象名 + 本场景用法；完整定义见 `shared-context.md` §3。

| 业务对象 | 业务对象英文 | 说明 |
|---|---|---|
| 内容 | Content | 本场景创建/编辑其基本信息区字段 |
| 内容类型 | ContentType | 创建时选择；创建后不可改 |
| 内容模板 | ContentTemplate | 创建时按内容类型带出默认值，可改选 |

## 3. 权限码

> 本 Epic 已登记的权限码见 `shared-context.md` §2；全局原则见 §4。

| 权限码 | 说明 | 本场景允许的操作 |
|---|---|---|
| `CONTENT_CREATE` | 内容新建 | 进入新建页、提交创建 |
| `CONTENT_UPDATE` | 内容更新 | 编辑基本信息并保存 |
| `CONTENT_VIEW` | 内容查看 | 查看详情（基本信息区） |

### 3.1 权限规则

- PR-001：请求方持有 `CONTENT_CREATE` 时，允许创建内容。
- PR-002：请求方未持有本场景所需权限码时，不允许执行对应操作。
- PR-003：当用户无权限访问数据时，系统应拒绝操作并返回明确错误原因。

## 4. 业务流程

### 4.1 主流程

1. 用户持 `CONTENT_CREATE` 进入「新建内容」。
2. 用户填写标题、选择内容类型、起止时间（可选说明）。
3. 系统按内容类型带出默认内容模板（允许改选）。
4. 系统校验字段与规则（见 §5 / §7）。
5. 系统创建 Content 记录，状态置为 `DRAFT`，返回内容 uuid。
6. 用户进入详情页继续配置展示信息与模块（另见 P-001-02）。

### 4.2 异常流程

| 编号 | 触发条件 | 系统行为 | 结果 |
|---|---|---|---|
| EX-001 | 必填字段缺失或格式非法 | 拒绝保存 | 返回字段级校验错误 |
| EX-002 | `endAt` 早于等于 `startAt` | 拒绝保存 | 返回时间区间非法错误 |
| EX-003 | 标题重复（见 R-CREATE-002） | 拒绝保存 | 提示标题已存在 |
| EX-004 | 编辑时内容类型被修改 | 拒绝保存 | 返回内容类型不可修改错误（E-R-002） |

## 5. 字段表

### 5.1 完整字段表（基本信息区）

| 字段名 | 中文名 | 类型 | 必填 | 描述 | 取值 / 枚举 / 来源 | 创建时必填 | 可修改 |
|---|---|---|---:|---|---|---:|---:|
| uuid | 内容唯一标识 | string | 是 | 对外唯一标识 | 系统生成 | 否 | 否 |
| title | 标题 | string | 是 | 运营命名，列表与详情展示 | 用户输入；长度 1–100 | 是 | 是 |
| contentType | 内容类型 | enum | 是 | 按用途分类 | 枚举：ANNOUNCEMENT=公告；HELP=帮助文档 | 是 | 否（E-R-002） |
| contentTemplate | 内容模板 | enum | 是 | 内容页版式 | 枚举：STANDARD=标准图文；GALLERY=图集；按内容类型带出默认值 | 是 | 是 |
| startAt | 生效开始时间 | datetime | 是 | C 端可见期起点 | 用户输入 | 是 | 是 |
| endAt | 生效结束时间 | datetime | 是 | C 端可见期终点；须晚于 startAt | 用户输入 | 是 | 是 |
| summary | 内容摘要 | string | 否 | 列表与分享卡片展示用 | 用户输入；长度 ≤200；v0.2 新增（见 `TECH-DESIGN-delta-v0.2-content-summary.md`） | 否 | 是 |
| remark | 内部备注 | string | 否 | 不对外展示 | 用户输入；长度 ≤200 | 否 | 是 |
| status | 内容状态 | enum | 是 | 生命周期状态 | 枚举：DRAFT=待发布；PUBLISHED=已发布；OFFLINE=已下线；创建时固定 DRAFT | 系统生成 | 否 | 按状态流转（P-001-03） |
| createdBy / createdAt | 创建人 / 创建时间 | string / datetime | 是 | 审计信息 | 系统生成 | 否 | 否 |
| updatedBy / updatedAt | 更新人 / 更新时间 | string / datetime | 是 | 审计信息 | 系统生成 | 否 | 否 |

## 7. 业务规则

### 7.1 通用规则

R-COMMON-001：审计信息记录

- 适用场景：COMMON
- 条件：创建或修改成功
- 动作：系统记录操作人与操作时间（createdBy/createdAt、updatedBy/updatedAt）

### 7.2 创建规则

R-CREATE-001：必填字段校验

- 适用场景：CREATE
- 条件：用户提交创建请求，且存在必填字段为空或格式非法
- 动作：系统拒绝创建，并返回字段级校验错误（EX-001）

R-CREATE-002：标题唯一性校验

- 适用场景：CREATE / UPDATE
- 条件：提交的 `title` 与既有**未删除**内容重复
- 动作：系统拒绝保存，并提示标题已存在（EX-003）

R-CREATE-003：时间区间校验

- 适用场景：CREATE / UPDATE
- 条件：`endAt <= startAt`
- 动作：系统拒绝保存，并返回时间区间非法错误（EX-002）

R-CREATE-004：初始状态

- 适用场景：CREATE
- 条件：创建成功
- 动作：系统将 `status` 置为 `DRAFT`；`uuid` 由系统生成并返回

R-CREATE-005：默认模板带出

- 适用场景：CREATE
- 条件：用户选择内容类型
- 动作：系统按 `ANNOUNCEMENT → STANDARD`、`HELP → GALLERY` 带出默认内容模板；允许用户改选（引用：E-R-002）

### 7.3 修改规则

R-UPDATE-001：内容类型不可修改

- 适用场景：UPDATE
- 条件：编辑保存时 `contentType` 与已存值不一致
- 动作：系统拒绝修改，并返回内容类型不可修改错误（引用：E-R-002；EX-004）

R-UPDATE-002：编辑权限校验

- 适用场景：UPDATE
- 条件：用户修改基本信息
- 动作：系统校验请求方是否持有 `CONTENT_UPDATE`；无权限码时拒绝修改

## 12. 验收标准

### 12.1 功能验收

AC-001：正常创建

- 给定：请求方持有 `CONTENT_CREATE`
- 当：用户输入合法字段并提交
- 则：系统创建成功，状态为 DRAFT，返回内容 uuid

AC-002：必填缺失

- 给定：请求方持有 `CONTENT_CREATE`
- 当：用户提交时缺失必填字段
- 则：系统拒绝创建，并返回字段级错误

AC-003：标题重复

- 给定：系统中已存在同名未删除内容
- 当：用户再次提交相同标题
- 则：系统拒绝保存，并提示标题已存在

AC-004：内容类型不可改

- 给定：内容已创建
- 当：编辑保存时修改 `contentType`
- 则：系统拒绝修改，并返回明确错误

AC-005：无权限访问

- 给定：请求方未持有对应权限码
- 当：用户创建或编辑
- 则：系统拒绝操作，并返回统一错误结果

### 12.2 数据验收

AC-DATA-001：创建成功后，数据库中必须存在对应业务记录（status=DRAFT）。
AC-DATA-002：修改成功后，业务字段和审计字段必须同步更新。

### 12.3 权限验收

AC-PERM-001：持有所需权限码的请求可以执行对应操作。
AC-PERM-002：未持有所需权限码的请求不能执行对应操作。
