## 1. 需求说明

### 1.1 需求名称

模块列表与模块框架（富文本 + 图片 + 视频）

### 1.2 需求类型

NEW

### 1.3 版本信息

NEW 需求，本节写「无」。

### 1.4 背景

内容页由可编排的模块列表组成。本 PRD 定义模块框架（公共结构 + 扩展约定）与首批三类模块；后续新模块类型按 E-R-003 登记后以新 PRD 接入。回链 Epic 背景见 `EPIC.md` §1。

### 1.5 目标

- 运营可为内容添加模块并调整顺序，模块按序渲染在内容页上。
- 首批支持富文本（正文）、图片（单图/图集）、视频（单视频）。
- 模块框架可扩展：新增类型不破坏既有配置。

### 1.6 范围

本次需求包含：

- 模块公共结构（moduleType / moduleTemplate / sortOrder / payload）
- 富文本模块（RICH_TEXT）
- 图片模块（IMAGE）
- 视频模块（VIDEO）
- 模块的新增 / 排序 / 删除（DRAFT 态）

## 2. 功能说明

### 2.1 功能概述

在内容详情「模块列表」区，运营选择模块类型 → 选择模板 → 填写载荷 → 保存；模块按 `sortOrder` 升序渲染。

### 2.2 适用场景（业务视角）

| 使用方 | 说明 | 典型场景 |
|---|---|---|
| 内容运营 | 内容页编排者 | 公告正文 + 配图 + 操作视频组合排布 |
| 客服运营 | 帮助内容维护者 | 帮助文档分步图文编排 |

### 2.3 主要业务对象

| 业务对象 | 业务对象英文 | 说明 |
|---|---|---|
| 模块 | ContentModule | 内容页模块实例；公共结构见 §5.1 |
| 富文本载荷 | RichTextPayload | 正文 HTML |
| 图片载荷 | ImagePayload | 图片 URL 列表（单图 / 图集） |
| 视频载荷 | VideoPayload | 视频地址 + 封面 + 可选标题 |

## 3. 权限码

| 权限码 | 说明 | 本场景允许的操作 |
|---|---|---|
| `CONTENT_UPDATE` | 内容更新 | 添加 / 排序 / 删除模块、保存载荷 |
| `CONTENT_VIEW` | 内容查看 | 查看模块列表与配置 |

### 3.1 权限规则

- PR-001：请求方持有 `CONTENT_UPDATE` 时，允许编排模块。
- PR-002：请求方未持有本场景所需权限码时，不允许执行对应操作。

---

## 4. 业务流程

### 4.1 主流程

1. 用户持 `CONTENT_UPDATE` 进入内容详情「模块列表」区。
2. 用户点击「+模块」，选择模块类型与模板。
3. 用户填写该类型载荷（见 §5.2 / §5.3 / §5.4）并保存。
4. 系统校验规则（§7）后保存模块，追加到列表末尾。
5. 用户通过上移 / 下移调整 `sortOrder`；可删除模块（DRAFT 态）。

### 4.2 异常流程

| 编号 | 触发条件 | 系统行为 | 结果 |
|---|---|---|---|
| EX-001 | 载荷必填项缺失或超长 | 拒绝保存 | 返回字段级校验错误 |
| EX-002 | 图集图片数量不在 2–9 范围 | 拒绝保存 | 返回数量非法错误 |
| EX-003 | 修改已保存模块的 moduleType / moduleTemplate | 拒绝保存 | 返回类型/模板不可修改错误 |
| EX-004 | 模块数超过上限 20 | 拒绝新增 | 返回模块数超限错误 |

## 5. 字段表

### 5.1 模块公共字段表

| 字段名 | 中文名 | 类型 | 必填 | 描述 | 取值 / 枚举 / 来源 | 创建时必填 | 可修改 |
|---|---|---|---:|---|---|---:|---:|
| uuid | 模块唯一标识 | string | 是 | 对外唯一标识 | 系统生成 | 否 | 否 |
| moduleType | 模块类型 | enum | 是 | 模块分类 | 枚举：RICH_TEXT=富文本；IMAGE=图片；VIDEO=视频（见 shared-context §3，可扩展） | 是 | 否 |
| moduleTemplate | 模块模板 | enum | 是 | 类型内展示模板 | 按 moduleType 取值，见 §5.2–§5.4 | 是 | 否 |
| sortOrder | 排序号 | number | 是 | 内容页渲染顺序，升序 | 系统维护；新增追加到末尾 | 否 | 是（经上移/下移） |
| payload | 模块载荷 | object | 是 | 类型相关配置 | 按 moduleType 对应 §5.2–§5.4 | 是 | 是（受锁定约束） |

### 5.2 RICH_TEXT 载荷字段

| 字段名 | 中文名 | 类型 | 必填 | 描述 | 取值 / 枚举 / 来源 |
|---|---|---|---:|---|---|
| richText | 正文 | string | 是 | 富文本 HTML | ≤20000 字符；经富文本编辑器产出 |

moduleTemplate 枚举：`ARTICLE`（正文段落）。

### 5.3 IMAGE 载荷字段

| 字段名 | 中文名 | 类型 | 必填 | 描述 | 取值 / 枚举 / 来源 |
|---|---|---|---:|---|---|
| images | 图片列表 | array | 是 | 图片项数组 | 每项 `{ url, alt }`；SINGLE_IMAGE 恰 1 张；GALLERY 2–9 张 |

moduleTemplate 枚举：`SINGLE_IMAGE`（单图）/ `GALLERY`（图集）。

### 5.4 VIDEO 载荷字段

| 字段名 | 中文名 | 类型 | 必填 | 描述 | 取值 / 枚举 / 来源 |
|---|---|---|---:|---|---|
| videoUrl | 视频地址 | string | 是 | 视频文件 URL | 上传获得 |
| coverImage | 封面图 | string | 是 | 封面图 URL | 上传获得 |
| title | 视频标题 | string | 否 | 展示标题 | ≤30 字 |

moduleTemplate 枚举：`VIDEO`（单视频）。

## 7. 业务规则

### 7.1 通用规则

R-COMMON-001：模块数上限

- 适用场景：CREATE
- 条件：新增后内容模块总数 > 20
- 动作：系统拒绝新增（EX-004）

### 7.2 创建规则

R-CREATE-001：类型与模板登记校验

- 适用场景：CREATE
- 条件：提交的 moduleType / moduleTemplate 未在 `shared-context.md` §3 登记（引用：E-R-003）
- 动作：系统拒绝保存

R-CREATE-002：类型与模板锁定

- 适用场景：CREATE / UPDATE
- 条件：模块保存成功后再次编辑
- 动作：moduleType / moduleTemplate 不可修改（EX-003）；载荷内容可改

R-CREATE-003：载荷校验

- 适用场景：CREATE / UPDATE
- 条件：保存模块载荷
- 动作：系统按 §5.2–§5.4 校验必填、长度与数量（图集 2–9 张）；不合法则拒绝（EX-001 / EX-002）

### 7.3 修改规则

R-UPDATE-001：排序调整

- 适用场景：UPDATE
- 条件：用户上移 / 下移模块
- 动作：系统交换相邻模块 `sortOrder` 并持久化；序号在内容内连续

R-UPDATE-002：编辑权限校验

- 适用场景：UPDATE
- 条件：用户编排模块
- 动作：系统校验请求方是否持有 `CONTENT_UPDATE`；无权限码时拒绝

### 7.4 删除规则

R-DELETE-001：DRAFT 态可删

- 适用场景：DELETE
- 条件：内容处于 DRAFT，用户删除模块
- 动作：系统逻辑删除模块并重排剩余 `sortOrder`

R-DELETE-002：已发布内容模块删除约束

- 适用场景：DELETE
- 条件：内容处于 PUBLISHED / OFFLINE
- 动作：本阶段**不允许删除模块**（后续编辑锁定细则由独立 PRD 承载）

## 12. 验收标准

### 12.1 功能验收

AC-001：添加富文本模块

- 给定：请求方持有 `CONTENT_UPDATE`，内容为 DRAFT
- 当：选择 RICH_TEXT / ARTICLE 并填写合法正文
- 则：模块保存成功并出现在列表末尾

AC-002：添加图片模块（图集）

- 当：选择 IMAGE / GALLERY 并上传 2–9 张图片
- 则：模块保存成功，图片按顺序保存

AC-003：图集数量非法

- 当：GALLERY 模板下只上传 1 张或超过 9 张
- 则：系统拒绝保存并返回数量非法错误

AC-004：类型 / 模板锁定

- 给定：模块已保存
- 当：编辑时修改 moduleType 或 moduleTemplate
- 则：系统拒绝保存

AC-005：排序

- 当：用户上移某模块
- 则：该模块与上一模块交换顺序，列表按新顺序渲染

AC-006：无权限

- 给定：请求方未持有 `CONTENT_UPDATE`
- 当：添加 / 删除模块
- 则：操作被拒绝

### 12.2 数据验收

AC-DATA-001：模块保存后，`(contentUuid, sortOrder)` 连续且唯一。
AC-DATA-002：载荷 JSON 与 moduleType 匹配（RICH_TEXT→richText；IMAGE→images；VIDEO→videoUrl 等）。

### 12.3 权限验收

AC-PERM-001：持有所需权限码的请求可以执行对应操作。
AC-PERM-002：未持有所需权限码的请求不能执行对应操作。

## 16. AI 实现提示

1. 新模块类型必须先在 `shared-context.md` §3 登记再实现（E-R-003）。
2. 不要在实现中新增本文档未定义的业务行为；每条规则映射至少一个测试用例。
3. 先读 `EPIC.md`，再读 `shared-context.md`，再读本 PRD。
4. 载荷按 moduleType 多态存储；公共字段（类型/模板/序号）独立于载荷演化。
5. 富文本 HTML 的净化（XSS）属实现层安全要求，不改变本文字段定义。
